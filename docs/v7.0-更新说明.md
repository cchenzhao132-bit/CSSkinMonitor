## 修复内容（按优先级）

### P0 · 7 日涨跌时间窗口不再静默降级（本次最核心修复）

**旧行为**：短历史数据下用 `priceHistory[length - 8]` 取「7 日前价」，数据不足 8 天时会退化成 15 天、45 天甚至更早的锚点，UI 却一律标注「7 日」——涨跌数字系统性失真。

**新行为**：

- 新增 `find7dAnchor`：按时间戳寻找「今天 − 7 天 ± 2 天」内的真实历史锚点
- 有第三方 7 日成交中位（`chgPrev`）的条目仍优先使用真实成交口径
- 找不到 7 日锚点（0/1/3 天短历史、仅剩 15/45 天锚点）→ 新增 `chgAvail=false`，UI 如实显示「**数据不足 / 7日锚点未积累到**」
- **禁止把 15/45 日前价格冒充 7 日涨跌**

### P0 · 涨跌阈值统一为单一配置

- 新增 `CHANGE_THRESHOLDS = { rising: 0.15, noticeable: 3, strong: 10, win7d: 2 }`（`crawler-templates/engine.js`）
- 榜单门槛（±0.15%）、涨跌分类（大涨 ≥10% / 上涨 ≥3% / 盘整 / 下跌 ≤−3% / 大跌 ≤−10%）全部引用统一配置
- 前端 `CHG_CLASS` 描述由 `window.__CHANGE_THRESHOLDS` 派生，删除散落魔法数
- 产品定义明确：**涨价榜 = 有 7 日数据且涨幅 > +0.15%**；**大涨 Chip = ≥ +10%**（两者是不同维度的语义，此前混为一谈）

### P0 · 历史数据边界防护（空/单点/非法价格不再崩溃）

详情页 `lowIdx / highIdx / pctBetween / volatility` 对以下输入全部安全处理：

- 空数组、单点历史 → 返回 null，UI 显示「—」
- 价格为 0 / null / NaN / Infinity / 负数 → 不产生 NaN，不抛异常
- 涨跌基准价必须为正数，否则标记数据不足

### P0 · 测试体系重构：断言业务不变量

新增 `tests/contract-audit.js`（`npm run test:contract`），覆盖：

| 测试组 | 内容 |
|---|---|
| 7 日时间窗口 | 0 / 1 / 3 / 7 / 8 / 15 / 45 天历史分别验证；稀疏锚点（仅 15/45 天）必须返回数据不足；非法日期防御 |
| 涨跌阈值临界值 | 0.14/0.15/0.16、2.99/3/3.01、9.99/10/10.01 及负值共 18 组 + null/NaN/Infinity 非法输入 |
| 历史边界防护 | 空/单点/0 价/null/NaN/Infinity 全部防护，正常数据计算正确 |
| findVariant 索引 | 索引查询与线性 find 全等（全库逐键比对） |
| 全库自洽 | listPrice/currentPrice 有限、chgAvail 与涨跌数字自洽、三榜守恒 |

`regression.js` 榜单断言从「验证当前实现自洽」改为「验证业务规则」（门槛、分类区间、无锚点不带涨跌数字），价格校验避开 `isFinite(null) === true` 陷阱。

### P1 · 性能与资源生命周期

- **`findVariant` 建 Map 索引**：磨损价位表渲染从 O(n) 全表扫描（3 万条 × 每单元格）降为 O(1) 查询
- **IntersectionObserver 生命周期治理**：榜单懒加载的 Observer 模块级保存，重建前 `disconnect()`（此前只生不灭）
- **搜索建议改事件委托**：快速打字不再反复绑定/累积 click 监听器

### P2/P3 · 其他

- 汇率（USD→CNY 固定 7.25）在爬虫注释与详情页 UI 明确标注「**固定参考汇率，非实时**」
- 收藏页排序/统计对无涨跌数据条目防护

### 测试稳定性

- 修复 `tests/alchemy-render.js` 时序竞态：15MB `data.js` 异步加载与骨架屏定时器竞争导致偶发误报，改为轮询等待渲染完成

## 使用说明

### 普通用户（桌面版）

桌面 `CSSkinMonitor.exe` 已更新为 v7.0 构建，同目录 `data.js` 已同步最新引擎与数据，**直接双击运行即可**。

### 开发者 / 自建

```bash

git pull origin main

# 重生成数据（可选；仓库内 app/data.js 为生成物不入库）
node crawler.js --regen
node build-fixture.js

# 跑全部测试
node regression.js --fixture
npm run test:contract
npm run test:alchemy

```

### 对数据的影响（重要）

- 7 日涨跌从「短历史用老锚点凑数」改为「**宁可显示数据不足，也不冒充 7 日**」
- 第三方参考条目（refOnly）在无真实历史时保持「无数据」标注，不再进榜
- **7 日窗口定义**：按「UTC 今天 − 7 天 ± 2 天」寻找锚点（与 crawler 快照的 UTC 日期口径一致）；±2 天容差吸收锚点稀疏/时区偏移，故标注「7 日」实际可能是 6~9 日窗口——这是有意的产品定义（宁可近似，不冒充），`win7d` 可在 `CHANGE_THRESHOLDS` 调整
- **模拟 vs 真实涨跌**：Steam 条目快照 <8 天时涨跌为本地模拟序列演示值，UI 已标注「模拟」（榜单行百分比旁 / 详情页 7 日数字旁与统计卡标签）；有真实快照或第三方成交中位的条目无此标注
- 榜单规模：涨价榜 / 降价榜 / 无变动榜三榜仍守恒（涨 + 无变动 + 跌 = 全库）
- 数据每一天都在积累：价格快照满 8 天后，涨跌自动从模拟/数据不足转为真实值

## 已知限制

1. **快照积累依赖每日定时任务**：`scripts/daily-refresh.bat` + Windows 计划任务 `CSSkinMonitor-DailyRefresh`（每日 9:00）负责 爬取→雷达→重建→同步桌面；任务未运行时快照不会增长（此前 8/29 之后曾断档，本次已补建）
2. **第三方回填锚点的 7 日近似**：Skinport 24h/7d/30d/90d 四锚点中「3 天前」锚点可能落入 7 日窗口容差内被用作基准——该条目有 `chgPrev`（真实 7 日成交中位）时优先用中位，无中位时用窗口内最近锚点（标注为数据不足的情况仅当窗口内无任何锚点）
3. **模拟涨跌不是交易依据**：标注「模拟」的数字仅用于界面演示，真实成交/快照数据满 8 天后自动替换
